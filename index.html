Network
User had no internet but everyone else on the floor was fine
Medium15 min fix
▼
Problem
User could not browse anything. Colleagues nearby had no issues.
Root Cause
Someone had manually set a static IP that clashed with another device on the same network.
Fix
Switched back to automatic DHCP, flushed DNS and renewed the lease. Internet came back straight away.
What I did
  • 1Checked if the problem was just this one person. It was only them, so I knew it was a device issue not a network outage.
  • 2Ran ping 192.168.1.1 to test the gateway. It responded, so the hardware was fine but the IP config was wrong.
  • 3Ran ipconfig /all and spotted a manually assigned static IP conflicting with another device on the subnet.
  • 4Went into Network Adapter settings, switched IPv4 to Obtain IP automatically, then ran ipconfig /release, /renew and /flushdns.
  • 5Confirmed with ping 8.8.8.8 and opened a browser with the user to make sure everything was back to normal.
Result
Back online in 15 minutes. Logged it and added a note that static IPs should only be set with IT approval.

Email
Outlook stopped syncing and emails were not coming through
High30 min fix
▼
Problem
Outlook looked up to date but new emails were not arriving and sending was silently failing.
Root Cause
Corrupted Outlook profile and an oversized OST cache file (18 GB) breaking sync with Exchange Online.
Fix
Built a new Outlook profile and deleted the old OST file. Full sync came back right away.
What I did
  • 1Tested Outlook Web App in the browser. Emails were arriving there fine, so the issue was the local Outlook client not the server.
  • 2Launched Outlook in safe mode to rule out add-ins. Issue still showed up, pointing to the profile or cache.
  • 3Went to Control Panel, opened Mail settings and created a new Outlook profile. Emails loaded immediately, confirming the old profile was corrupt.
  • 4Found the old .OST file in AppData and deleted it. It was 18 GB, well over the healthy limit. Outlook created a fresh one automatically.
  • 5Set the new profile as default, restarted Outlook and confirmed all folders, calendar and contacts were syncing correctly.
Result
Email fully working in 30 minutes. Added OST file size checks to the team preventative maintenance list.

Hardware
Shared office printer went offline and jobs were stacking up
Medium20 min fix
▼
Problem
The shared printer showed offline for the whole floor. Jobs kept queuing but nothing was printing.
Root Cause
The Print Spooler service had crashed due to a stuck job. Two machines also had outdated drivers.
Fix
Cleared the stuck jobs, restarted the Spooler service and pushed updated drivers to affected machines.
What I did
  • 1Pinged the printer's IP address. It responded fine, so the hardware was on and connected. The issue was software side.
  • 2Opened Services.msc and found the Print Spooler was stopped. Tried restarting it but it crashed again because of a stuck job.
  • 3Stopped Spooler, went into C:\Windows\System32\spool\PRINTERS and deleted all files inside. Then restarted Spooler successfully.
  • 4Set the printer back to online and sent a test print. It went through straight away.
  • 5Pushed updated printer drivers from the print server to two machines that had outdated versions.
Result
Everyone was printing again within 20 minutes. Wrote up the Spooler restart steps so any team member could handle it next time.

Performance
PC was taking over 10 minutes to boot and freezing throughout the day
Medium45 min fix
▼
Problem
User said their PC was painfully slow all day and took more than 10 minutes just to get to the desktop.
Root Cause
23 startup programs running, hard drive 97% full with only 4 GB free, and Windows Update running silently during work hours.
Fix
Disabled startup programs, freed 15 GB of temp files and set Windows Update to run outside business hours.
What I did
  • 1Opened Task Manager, Startup tab. Found 23 programs launching at startup. Disabled everything non-essential.
  • 2Checked the Performance tab during reboot. Disk was at 100%. Traced it to Windows Update downloading in the background during work hours.
  • 3Ran Disk Cleanup and cleared temp files, Windows Update cache and the Recycle Bin. Freed around 15 GB.
  • 4Set Windows Update Active Hours to 8am to 6pm so updates only download outside of work time.
  • 5Rebooted and timed it. Machine reached the desktop in 88 seconds. CPU and disk both under 30% at idle.
Result
Boot time went from over 10 minutes down to 88 seconds. Flagged the machine for an SSD upgrade in the next hardware refresh.

Software
Software install kept failing with Error 1603
Medium25 min fix
▼
Problem
User needed to install business software but kept getting Error 1603 every time.
Root Cause
No local admin rights, plus a corrupt registry key left by a previous failed install attempt.
Fix
Removed the stale registry entry and ran the installer as admin. Completed without issues.
What I did
  • 1Checked Event Viewer Application logs. Found Event ID 11708 pointing to an MSI permissions failure.
  • 2Confirmed the user was a standard account. Right-clicked the installer and chose Run as Administrator. Still failed.
  • 3Found a leftover registry key from a previous failed attempt. Exported a backup then deleted the stale entry.
  • 4Cleared the %temp% folder to remove any cached installer files that could interfere.
  • 5Ran the installer as Administrator again. Completed successfully. Confirmed it worked under the user's account.
Result
Software installed and working within 25 minutes. Added a note to always clear temp files and check for leftover registry entries before reinstalling.

VPN
Remote worker could not connect to VPN and was completely unable to work
High20 min fix
▼
Problem
Remote employee's VPN authentication kept failing even with the right password.
Root Cause
MFA authenticator had time drift causing invalid codes. VPN client was also outdated and incompatible with the server.
Fix
Re-synced the authenticator time and updated the VPN client. Connected first try after that.
What I did
  • 1Asked the user to log into the M365 web portal. That worked fine, so the account was not locked. The issue was VPN-specific.
  • 2Checked the Authenticator app. Codes were generating but the app's time was slightly out of sync. Walked them through enabling automatic time sync.
  • 3Tried VPN again. Still failed. Checked the client version and found the user had v4.6 but the server now required v5.x minimum.
  • 4Sent a download link for the latest VPN client and walked them through installing it over the phone.
  • 5User connected successfully. Confirmed access to internal file shares and the company intranet.
Result
Remote worker back online in 20 minutes. Sent a notice to the rest of the remote team about the VPN update so no one else hit the same issue.
